01 / DOMAIN & DATA

Why e-commerce, and where 5 million rows come from

E-commerce is the richest domain for a portfolio: it produces a genuine star schema (orders, items, customers, products, payments, sellers, reviews), it has a natural transactional source that changes constantly — perfect for CDC — and volume is easy to scale honestly.

The source of truth

OLTP Postgres

A normalized operational database (customers, orders, order_items, products, payments) — the system a real shop would run on. Seeded once, then mutated continuously.

Reaching scale honestly

Synthetic generator

A Python + Faker generator produces a coherent history: ~250k customers, 50k products, 2M orders → 5.4M order-items, with realistic seasonality, price distributions, and status lifecycles.

Optional real anchor

Public datasets

The schema mirrors the Olist Brazilian e-commerce dataset, so the same models run against real data. Instacart (3M orders) and Amazon Reviews are drop-in extensions.

Two ingestion modes, one source

The batch path bulk-loads history from Postgres via Spark JDBC. The CDC path captures every INSERT / UPDATE / DELETE from the Postgres write-ahead log in near-real-time. An order that moves placed → paid → shipped → delivered emits four CDC events — that lifecycle is exactly what makes the streaming story real.

02 / ARCHITECTURE

Full pipeline: from write-ahead log to homepage

The stack splits cleanly in two. A local Docker plane runs the sources and streaming ingestion; the cloud lakehouse on Databricks does transformation and serving. Object storage is the seam between them — a deliberate design forced by, and turned to advantage from, Free Edition's network limits.

03 / CHANGE DATA CAPTURE

How one row change becomes a gold-layer fact

The CDC path is the centerpiece. Debezium reads Postgres's logical replication slot, so the platform never polls the database — it reacts to the write-ahead log itself.

05 / MEDALLION LAYERS

What lives in bronze, silver, and gold

Bronze — Raw
  • Exact copy of source, append-only
  • CDC envelope kept: op, ts_ms, before/after
  • Batch snapshots landed as-is
  • No business logic, nothing dropped
format: Delta · load: MERGE + append
Silver — Conformed
  • Typed, deduplicated, latest-state per key
  • Soft-delete tombstones resolved
  • Standardized units, currencies, timezones
  • Referential joins validated
format: Delta · engine: Spark + dbt
Gold — Star schema
  • Kimball facts + conformed dimensions
  • SCD-2 history on customer & product
  • Pre-aggregated marts for the dashboard
  • Fully tested & documented in dbt
format: Delta · consumer: SQL + Streamlit
06 / DIMENSIONAL MODEL

The gold-layer star schema

Grain matters: the primary fact is one row per order line item. That single decision makes revenue, units, discounts, and basket analysis all additive and trivially correct.

08 / BUILD ORDER

How it gets built, in shippable slices

P0

Foundation & data generator

Repo scaffold, Docker Compose (Postgres + Kafka + Connect + MinIO), and the Faker generator that seeds 5M+ coherent rows into Postgres.

→ deliverable: docker compose up yields a populated OLTP DB
P1

Batch ingestion

PySpark JDBC job lands full + incremental snapshots to object storage as partitioned Parquet/Delta.

→ deliverable: bronze tables from batch
P2

CDC streaming

Register the Debezium Postgres connector; Spark Structured Streaming consumes Kafka and MERGEs into bronze Delta.

→ deliverable: near-real-time bronze
P3

dbt transforms

Silver conforming models + the gold star schema with SCD-2 dims, dbt tests, and docs.

→ deliverable: queryable star schema
P4

Analytics homepage

Streamlit app on the SQL warehouse: revenue trend, top categories, cohort retention, live order feed.

→ deliverable: the shareable dashboard
P5

CI/CD & orchestration

GitHub Actions gates + Databricks Asset Bundle deploy + scheduled Workflows. Optional Terraform for cloud objects.

→ deliverable: push-to-deploy platform
